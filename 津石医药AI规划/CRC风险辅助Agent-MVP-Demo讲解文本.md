# CRC 风险辅助 Agent MVP Demo 讲解文本

> 适用场景：内部评审、客户汇报、早期用户试点说明
> 讲解时长：约 8-10 分钟
> 对应文档：本体设计（10 实体）、AI 机会地图（opp_03/opp_11 主场景）、AI 产品画布 V2-MVP

---

## 一、开场：产品定位（1 分钟）

大家好，今天演示的是**津石医药 CRC 访视风险智能助手 MVP**。

先说明一个核心判断：在临床试验现场，CRC 每天同时处理访视执行、资料补传、受试者状态跟踪、AE/SAE/CM 线索确认和状态更新，容易遗漏下一步动作。我们原本设想让 AI 同时服务医生和医院系统，但在落地评估中发现，医院 HIS/EMR 接口封闭、商务周期不可控，医生决策场景责任边界也过高。

因此，本轮 MVP 把产品边界严格收缩为**CRC 独立工具**：

- **目标用户**：CRC 和 CRC 组长；
- **数据来源**：CRC 手动上传检查单、访视记录等源文件；
- **核心能力**：把检查单中的检验指标抽取出来，映射 CTCAE / SOP / AE 规则，识别受试者状态异常线索并生成复核证据包；
- **输出形态**：AI 把风险信号转成 CRC 可执行的下一步动作、待研究者确认的问题清单和 EDC 回填建议；
- **医学确认**：所有涉及临床判定的内容，仍需 CRC 在线下获取研究者确认后再回填。

一句话总结：**AI 不做诊断、不定级、不上报、不替代医生，只做 CRC 行政与数据效率的辅助。**

## 二、页面布局（1 分钟）

现在大家看到的是 Demo 工作台，三栏布局。

**左侧**是今日访视队列，共 3 个任务：

- `PV-031`（红色，**MVP 主场景**）：高风险，走完整的异常预判 → 人工确认 → 动作闭环链路；
- `PV-019`（黄色，**路线图**）、`PV-044`（绿色，**路线图**）：仅作范围说明，非本轮 MVP 主链路。

**中间**是 5 步工作流，对应本体设计的工作流：

1. 访视上下文（范围与资料核对）
2. AE/SAE/CM 预识别（证据抽取与候选映射）
3. 医生确认（线下指令结构化）
4. 动作与 EDC 建议（闭环执行草稿）
5. 反馈学习（知识优化候选）

**右侧**是**访视协作侧栏**，四个结构化面板，全部为预设数据、不连接 LLM：

- 待确认问题清单（来自复核证据包）；
- 规则命中依据（CTCAE / SOP / AE 规则）；
- 证据时间线（源文件与检验指标的加工节点）；
- 人机权限边界（AI / CRC / 研究者各自可做与不可越过）。

> 需要强调：侧栏替代了早期的“对话式 AI 助手”。MVP 不接入 LLM 对话，规避了大模型接入的复杂度和费用，用结构化证据面板达成同样的“可追溯、不越权”目标。

## 三、案例 1：PV-031 高风险主场景（4 分钟）

我们点击队列里的 `PV-031`。受试者 **JSM-1024**，项目 JS-ONC-III，天津中心 A03，V3/D15 访视，综合风险分 86。

### 3.1 第 1 步 · 访视上下文

系统自动锁定访视窗口、检查单、症状记录、合并用药四项范围核对。症状记录为“发热、乏力、皮疹”，合并用药含新增退热药待补剂量——这些上下文全部来自 CRC 上传的资料，**不需要对接医院 HIS/EMR**。

### 3.2 第 2 步 · AE/SAE/CM 预识别

点击“载入模拟检查单”，观察解析动画：**版面识别 → 检验指标标准化 → 时间对齐 → CTCAE / SOP / AE 规则检索**。

载入后左右联动：

- 左侧是模拟化验单原文，点击体温 `38.3°C`、中性粒细胞 `0.82×10⁹/L`、血小板 `72×10⁹/L`、ALT `128 U/L` 等数值，右侧指标卡高亮；
- 右侧是**5 个已抽取的检验指标**，每个带 CTCAE 候选映射和置信度：ANC 候选 Grade 3、血小板候选 Grade 2、ALT 候选 Grade 2、体温命中发热条目、肌酐未命中阈值。

下方“检索增强证据”展示 3 条规则命中：CTCAE v5.0（94%）、项目 SOP-CR-03（91%）、安全事件规则库 AE-02（88%）。引用可追溯，不替代医学判断。

右上角明确标注：**高优先级人工确认**，且“系统不诊断、不定级、不自动上报”。

此时右侧协作侧栏自动更新：

- **待确认问题清单**：① 是否确认为新发 AE（先核对是否与既有 AE-2026-0718-01 重复）；② 严重程度与 CTCAE 等级；③ 与研究药物的因果关系；④ 是否满足 SAE 标准、是否需快速上报；⑤ 复测与处置要求。
- **规则命中依据**：与中间页一致的 3 条规则。
- **证据时间线**：08:12 检查单采样 → 09:03 检验报告审核完成 → 09:15 报告上传待复核 → 09:20 AI 预识别完成。

### 3.3 第 3 步 · 医生确认

研究者不直接登录本工具。CRC 根据线下沟通（面谈 / 电话 / 院内合规渠道），在模板中选择或编辑医生指令，回填人工结论与确认来源，形成结构化留痕。

- 演示勾选右侧“待确认问题清单”的若干项，回显“已勾选，可作为医生确认步骤的待办引用”；
- 人工结论可选“暂不判断，补充证据后复核 / 确认为 AE / 既有 AE 的补充信息 / 排除候选”；
- 强调“暂不判断”不等于“无风险”，风险状态保持开放。

### 3.4 第 4 步 · 动作与 EDC 建议

人工结论转成 4 条可执行动作，每条含优先级、截止时间、关闭标准：

- 补充体温与血常规复测（紧急，今日 15:30 前）；
- 补全症状起止时间（高，今日 17:00 前）；
- 核对合并用药 CM 记录（高，今日下班前）；
- 生成 EDC 回填草稿（中，证据补齐后 2h）。

下方 EDC 回填草稿基于人工结论预填 AE/CM 字段，但**不自动提交**——必须由授权 CRC 人工核对后登录 EDC 提交。

### 3.5 第 5 步 · 反馈学习

CRC 提交“知识优化候选”（例如：候选同时命中 ANC 降低与发热条目，建议在证据包中优先展示联合线索）。系统强调：

- 单次反馈不能直接修改线上 RAG；
- 必须经 CRC 组长复核 → 规则所有者批准 → 版本发布与回归测试，才会用于后续判断；
- 当前线上知识版本 `RAG-CRC v1.6.2` 不变。

## 四、案例 2：PV-019 与案例 3：PV-044（1 分钟）

这两个任务在队列中标为**路线图**，非本轮 MVP 主链路，演示时一句话带过：

- `PV-019`（中风险）：ICF 版本不一致，需补传 v1.2 并更新资料状态——属于“资料完整性”备用场景，体现对低风险事务性工作的统一提醒；
- `PV-044`（低风险）：确认受试者今日到访并上传预约确认记录——轻量提醒，避免提醒疲劳。

## 五、三个场景分支（1 分钟）

页面顶部有三个切换按钮，用于展示不同侧面：

1. **主流程**：刚才演示的完整链路；
2. **数据冲突**：LIS 采样时间（07:46）与检查单（08:12）不一致，系统保留两侧原始时间并要求人工核对——右侧证据时间线会多出冲突节点；
3. **资料缺失**：缺少 CM 与症状起止时间，预识别可继续，但结果必须标记“证据不完整”，不能把未观察到解释为无风险。

## 六、边界护栏（1 分钟）

右侧“人机权限边界”面板和页面各步的决策提示共同构成 5 条行动边界（对应本体设计 action_boundaries）：

1. **访视上下文（ab_next_action）**：AI 只汇总风险与排序动作，不自动关闭访视、无规则依据不强推、不把风险评分解释为医学严重程度；
2. **受试者异常预判（ab_subject_abnormal）**：只给线索，不输出最终临床判定、不判定受试者是否安全、不隐藏低置信度提示；
3. **复核证据包（ab_review_packet）**：只整理事实和问题，不伪造或补写研究者结论、不用 AI 摘要替代原始证据、证据包未确认不进升级；
4. **AE/SAE/CM 升级（ab_ae_sae_cm）**：不自动判定成立、不自动提交上报、资料不全时触发补齐任务而非取消升级提示；
5. **反馈学习（ab_feedback_learning）**：不用单次反馈直接改规则、不把“忽略提醒”视为模型错误、不把 CRC 反馈当作临床真值。

## 七、总结：这个 Demo 想证明什么？（1 分钟）

1. **聚焦 CRC 独立工具**：不依赖医院系统接口，CRC 手动上传即可使用，落地可行性高；
2. **AI 边界清晰**：右侧为结构化协作侧栏，无 LLM 对话，规避接入复杂度与费用；只辅助行政和数据效率，不替代研究者临床判定，不自动上报；
3. **闭环可度量**：从风险识别、动作提醒、复核证据包到反馈学习，形成 CRC 可执行、可关闭、可追踪的完整链路。

下一步建议：选择 1-2 个研究中心的 CRC 进行本地 Web 工具试点，重点验证检验指标抽取准确率、CTCAE 规则命中率和 CRC 采纳率。
